# Обязательный первый шаг — проверка дубликата

Прежде чем читать или трогать черновой урок в Notion — **всегда**, для любого урока, спроси Оксану:

> «Ты сделала дубликат черновика этого урока в свой личный Notion (резервную копию)?»

- Если ответ «нет» или подтверждения нет — останавливаешься. Не читай и не редактируй страницу урока через Notion MCP, пока не получишь подтверждение.
- Если ответ «да» — можно приступать к чтению, а после утверждённых правок (шаг 3) — сразу вносить их в Notion, **без** дополнительного запроса разрешения на каждую отдельную операцию записи. Резервная копия — это и есть разрешение.

Правило постоянное, действует при каждом запуске skill, а не только на тестах.

# Входные параметры

Оксана передаёт в диалоге при вызове:
1. `draft_url` — ссылка на черновой урок (Notion)
2. `sample_url` — ссылка на урок-образец (Notion)
3. `scenario_url` — ссылка на сценарий текущего урока (Notion)
4. `next_scenario_url` — ссылка на сценарий следующего урока (Notion)
5. `video_timing` — тайминг каждого видео урока по порядку (например: `1:43, 11:03, 5:33...`)

# Источники контекста курса (локальные файлы этого репозитория, `context/`)

- `context/course-program.md` — учебная программа курса → для блока «Что мы умеем»
- `context/m7-practice.md` — практика модуля M7 → для ДЗ
- `context/methodist-bible-timing.md` — формула расчёта тайминга

Если какого-то из файлов ещё нет — сообщи об этом и попроси Оксану добавить, не угадывай содержание программы или практики.

# Шаг 1. Чтение и сопоставление структуры

1. Получи markdown чернового урока и урока-образца (Notion MCP, например `API-retrieve-page-markdown`).
2. Получи блочную структуру черновика (`API-get-block-children`) — понадобится для точечных правок конкретных блоков, а не перезаписи всей страницы.
3. Сопоставь разделы черновика с ожидаемой структурой урока: Что мы умеем → Результат дня → Время → Теория → (Словарь) → (Доп. материалы) → ДЗ → (На следующем занятии). Отметь расхождения с образцом.
4. Прочитай markdown сценария текущего и следующего урока тем же способом.

# Шаг 2. Формализуемые правки — вносятся сразу, без подтверждения текста

- **Что мы умеем** — на основе `course-program.md`: что пройдено к этому уроку.
- **Названия разделов** — сверь название каждого раздела с его содержимым и с образцом; если не соответствует — исправь.
- **На следующем занятии** — сформируй по сценарию следующего урока.
- **Тайминг** — считай **после** утверждения ДЗ (шаг 3), потому что нужна оценка времени на его выполнение:
  - время чтения/просмотра = сумма длительностей видео (`video_timing`) + 10–15 минут;
  - время выполнения ДЗ = экспертная оценка по сложности задания — единой формулы нет, ориентируйся на то, сколько времени эксперт тратит на аналогичное в самом уроке, и на уровень сложности ДЗ.

Эти правки вносятся в Notion сразу после подтверждения дубликата (шаг 0), без дополнительного запроса.

# Шаг 3. Содержательные правки — показать текст, дождаться подтверждения

Для каждого пункта: сформулируй правку → покажи текст в диалоге → дождись «ок» или правок от Оксаны → только после этого вноси в Notion.

- **Результат дня** — сократи/объедини пункты после автотранскрибации, по аналогии с образцом.
- **ДЗ** — практикоориентированное, покрывает содержание урока; опирайся на `course-program.md`, `m7-practice.md` и сценарий текущего урока; оформление — как в уроке-образце.
- **Теория** — проверь текст (после отдела транскрибации) на логичность и соответствие теме, предложи правки при необходимости.
- **Доп. материалы** — проверь и при необходимости дополни.

# Шаг 4. Стиль оформления — всегда сверяй с образцом

- Общий стиль блоков (toggle / обычный текст) должен совпадать с уроком-образцом, раздел за разделом.
- Текст сразу под первым видео — без toggle, если так оформлено в образце. Toggle используется там, где перед видео есть вступление, оформленное как toggle в образце.
- Не трогай служебные toggle **«Разработка урока»** и **«Архив кадр без стрелок»** — это внутренние технические блоки, не часть содержания урока для студента.

# Шаг 5. Отчёт

После внесения всех правок — краткий текстовый список изменений по каждому пункту (шаги 2 и 3), для быстрой сверки Оксаной. Дополнительно сохрани его в `reports/<дата>-<код урока>-changes.md`.
